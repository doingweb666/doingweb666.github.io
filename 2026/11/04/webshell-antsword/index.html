【课后作业】一句话木马与蚁剑：Web 权限维持的最小实现

date 2026-11-04 • read 11 min • dir 渗透实战 #一句话木马 #蚁剑 #WebShell #权限维持

如果 Meterpreter 是”重型装甲”，那 WebShell 就是”一把藏得极好的一字螺丝刀”。一行 PHP 代码，几 KB 不到，混在一堆正常的 PHP 文件里几乎无法用肉眼分辨，却能让你以 Web 服务的权限永久控制整台服务器。

这篇记录一句话木马的写入与蚁剑（AntSword）的连接使用。

⚙️ 实验环境

  • 攻击机：Windows 10（192.168.80.1）+ 蚁剑 AntSword v4.0.3（D:\AntSword-Loader-v4.0.3-win32-x64）
  • 靶机：phpstudy + Pikachu（http://127.0.0.1，Apache 监听 80）或 DVWA
  • 目标：拿到 Web 目录的写权限（通过上传漏洞、文件包含或直接放置）

🧬 原理：一行代码为什么能控制服务器

拆开看：

  • $_REQUEST['cmd'] —— 接收客户端传来的 cmd 参数，值完全由攻击者控制
  • system() —— 把参数内容当作系统命令执行，并回显输出

蚁剑用的变体是 eval：

区别在于 eval 执行的是 PHP 代码而不是系统命令，能力更强（能调 PHP 函数、操作文件、连数据库），也是 AntSword 默认解析的格式。前面的 @ 抑制错误输出，避免报错信息暴露路径。

这里有个新手最容易踩的坑：很多教程写的是 $_POST['cmd']，而 $_POST 只接收请求体，浏览器地址栏里 ?cmd=... 发的是 GET —— 结果就是打开页面一片空白，让人以为木马坏了。其实不是木马的问题，是参数根本没进去。换成 $_REQUEST（GET / POST / COOKIE 全收）两种方式都能用，蚁剑走 POST 也不受影响。

🛠️ 第二步：蚁剑连接

打开 AntSword.exe，右键「添加数据」：

字段 填写
URL 地址 http://127.0.0.1/shell.php
连接密码 cmd（与代码里的参数名一致）
编码器 default（若被 WAF 拦可换 base64）
网站类型 PHP

点「测试连接」，显示成功即可保存。双击进入后，蚁剑会自动探测目标环境（PHP 版本、OS、当前用户、可执行函数、禁用函数清单），在界面右上角能看到。

🎛️ 第三步：能做哪些事

文件管理：像用资源管理器一样浏览服务器目录，可以上传、下载、编辑、改权限、批量打包。找一个可写的 Web 目录传个新的木马，就是”权限维持”。

虚拟终端：直接执行系统命令。如果目标禁用了一堆危险函数，蚁剑会提示哪些可用、哪些被 disable_functions 挡住了。

进去的第一眼，蚁剑就把目标摸清了：系统是 Windows NT 10.0 build 26200、当前是 AMD64、Web 根目录在 D:/phpstudypro/WWW、跑 PHP 的身份是普通用户。这一步不需要任何提权动作，因为 Web 服务本身就是用这个身份在跑。

数据库管理：填入 MySQL 的连接信息后可以直接执行 SQL —— 通常配置文件里就有明文账号密码（config.inc.php 之类）。

插件市场：提权辅助、端口扫描、反弹 shell、内网代理，都能一键加载。

编码器与流量混淆：base64、chr、rot13 等编码器会把 POST 内容变形，绕过基于关键字匹配的 WAF。这也是”为什么光靠正则拦 webshell 没用”的原因。

🔍 怎么发现它

防守方拿到一台疑似被控的服务器，通常这样查：

1. 找异常文件

真实环境里攻击者会混淆，实际形态可能是 $_POST['a'.'b']、base64_decode、preg_replace 加 /e（老版本）、或者藏在一个看起来正常的 404.php 里 —— 所以还要看文件修改时间和文件大小异常。

2. 看访问日志
大量带 cmd=、pass= 参数的 POST 请求，或者同一个 IP 短时间内访问同一个陌生 PHP 文件。

实测的 access.log 就是这样暴露的：

能读出三件事：

  • GET 请求带明文参数：cmd=system(%27whoami%27)，%27 是单引号的 URL 编码 —— 请求内容完全没有加密
  • POST 请求只留长度：POST /shell.php HTTP/1.1" 200 112，正文不进日志，所以蚁剑默认走 POST 比 GET 隐蔽
  • 中间那批 404：正是文件被火绒删掉、木马还没重新落地的时间段 —— 连”攻击者遇到挫折”都记下来了

3. 工具扫描
D盾、河马、微步在线云沙箱的 webshell 检测，对已知家族检出率不错。

4. 主机侧
disable_functions 有没有被改、.htaccess 有没有被塞内容、crontab 有没有陌生任务 —— webshell 常伴随权限维持动作。

🛡️ 怎么防

层次 措施
代码 上传功能做扩展名白名单 + 内容检测 + 重命名，上传目录禁止执行 PHP（php_flag engine off）
配置 disable_functions 禁用 system/exec/eval/passthru 等；open_basedir 限制可访问目录
权限 Web 服务以低权限用户运行，目录不给写权限（这条最有效）
流量 WAF 检测 POST 中的代码特征；出站限制，防止反弹
检测 文件完整性监控（FIM）、定期 webshell 扫描、日志告警
应急 发现后不要只删文件 —— 要查它怎么进来的（上传点/注入点/弱口令），否则删了还会再来

一句话总结：webshell 的根因是”能让不可信内容写进可执行目录”。把这条路径堵死（写权限分离、上传目录不可执行），90% 的 webshell 就没法落地。

📌 补充说明

  • 一句话木马 vs 大马：一句话木马体积小、功能弱（只负责执行代码），靠客户端（蚁剑/菜刀）提供交互能力；大马是功能完整的网页管理面板，体积大易被查杀。现代趋势是”一句话 + 客户端”，因为服务端越干净越难发现。
  • 蚁剑和菜刀的关系：蚁剑是”中国菜刀”的开源替代，修掉了菜刀的几个致命问题（明文流量、固定特征），并支持插件和自定义编码器。
  • 合规边界：本文全部操作在本地自建靶场完成。向任何你无权控制的服务器写入 webshell，属于《刑法》第 285 条第二款的非法控制计算机信息系统罪，量刑起点是三年以下有期徒刑。
